# Python Implementation Specification for Quant Trading Research Bot

This specification tells Claude Code how to build the research/backtesting project. The first version is a research bot, not a live trading bot.

============================================================
PROJECT PRINCIPLES
============================================================

1. Build modular research infrastructure.
2. Implement strategies as independent modules.
3. Use realistic transaction costs.
4. Prevent look-ahead bias.
5. Prefer conservative risk controls.
6. Generate readable reports.
7. Do not implement live trading in v1.

============================================================
DATA SCHEMAS
============================================================

## OHLCV Schema
Required columns:
- timestamp or date
- symbol
- open
- high
- low
- close
- adjusted_close
- volume

Optional columns:
- bid
- ask
- spread
- dividend
- split_factor
- sector
- industry
- market_cap

Validation rules:
- no duplicate date-symbol rows
- high >= low
- high >= open, close
- low <= open, close
- adjusted_close positive
- volume nonnegative
- missing data handled explicitly, never silently converted to zero

## Options Chain Schema
Required columns:
- timestamp or date
- underlying
- expiration
- dte
- option_type: call or put
- strike
- bid
- ask
- mid
- last optional
- volume
- open_interest
- implied_volatility
- delta
- gamma
- theta
- vega
- rho optional
- contract_multiplier
- exercise_style if known

Validation rules:
- bid <= ask
- mid = (bid + ask) / 2 unless provided
- reject zero bid/ask when inappropriate
- reject wide spreads by threshold
- check DTE and expiration consistency

## Futures Chain Schema
Required columns:
- date
- root_symbol
- contract
- expiration
- settlement
- volume
- open_interest

Optional:
- bid
- ask
- first_notice_date
- roll_date

============================================================
CORE CLASSES
============================================================

## Strategy Base Class
Each strategy should implement:
- prepare_data(data)
- generate_signals(data)
- generate_target_weights(signals, portfolio_state, risk_config)
- explain_signal(symbol, date)

Outputs:
- DataFrame of signals with date, symbol, signal, confidence, expected_holding_period, reason
- DataFrame of target weights

## RiskManager
Responsibilities:
- volatility targeting
- max position caps
- max gross/net exposure
- max sector exposure
- drawdown limits
- kill switch
- VaR/ES calculation where possible
- options Greeks limits

## TransactionCostModel
Responsibilities:
- commissions
- slippage
- bid/ask spread
- market impact approximation
- options multi-leg spread costs
- cost filter: expected_edge > cost_multiplier * round_trip_cost

Suggested simple v1 model:
- equities/ETFs: commission_per_share + spread_bps + slippage_bps
- options: per_contract_fee + bid_ask_fraction + multi_leg_penalty
- futures: per_contract_fee + tick_slippage

## PortfolioConstructor
Methods:
- equal_weight(signals)
- inverse_vol_weight(signals, vol)
- volatility_target(weights, vol_target)
- apply_constraints(weights, constraints)
- combine_strategy_weights(strategy_weight_dict)

## BacktestEngine
Responsibilities:
- iterate through dates
- pass data to strategies
- generate target weights
- create orders
- simulate fills
- update positions/cash/equity
- record metrics

Must prevent look-ahead:
- Signals generated using data available up to date t.
- Trades executed at next open or next close according to config.
- Never use future data for pair selection, factor ranking, IV, or volatility forecast.

## Structures Module
src/quantbot/options/structures.py

Create classes:
- OptionLeg
- OptionStructure
- VerticalSpread
- IronCondor
- Straddle
- Strangle
- CalendarSpread

Each structure should compute:
- net debit/credit
- max profit if definable
- max loss if definable
- breakevens if possible
- net Greeks
- scenario PnL

## Greeks Module
src/quantbot/options/greeks.py

Implement Black-Scholes-style Greeks for research:
- delta
- gamma
- theta
- vega
- rho

Use for approximation only. For American options or real trading, label limitations.

## Put-Call Parity Module
src/quantbot/options/parity.py

Functions:
- put_call_parity_value(call, put, strike, rate, dte, dividend_yield=0)

- scan_box_spreads(chain, cost_model)
- scan_butterfly_convexity(chain)

In v1, scanner should not auto-trade.

============================================================
TESTING REQUIREMENTS
============================================================

Minimum tests:
1. Data validation catches impossible OHLC values.
2. Trend signal does not use future returns.
3. Backtest engine executes after signal date, not before.
4. Transaction costs reduce performance.
5. Position caps are enforced.
6. Pairs strategy exits at exit_z and stop_z.
7. Options payoff functions match known payoff shapes.
8. Put-call parity scanner handles bid/ask and does not flag false opportunities without cost buffer.

============================================================
DO NOT DO IN V1
============================================================

- Do not connect to a live broker.
- Do not place live trades.
- Do not use naked short options.
- Do not build HFT or market-making assumptions.
- Do not optimize parameters aggressively.
- Do not ignore dividends, splits, or corporate actions for equities.
- Do not trust options last price as executable price.

============================================================
FINAL EXPECTED OUTPUT FROM CLAUDE CODE

A working Python research repo that can:
1. Load OHLCV data.
2. Validate data.
3. Run S01 trend following backtest.
4. Run S03 pairs backtest.
5. Generate performance report.
6. Include cost and risk models.
7. Include options payoff/parity utilities for later expansion.
8. Include tests.
